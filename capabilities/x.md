# X

## CLI boundary

The CLI can create/populate a watch List, watch searches or Lists, read the operator's published history, and stage tweet, thread, Article, or reply drafts. It never publishes or schedules content.

The agent is responsible for choosing the action and format, supplying final text/Markdown and any Article cover, and checking the native draft when the receipt cannot prove full persistence. The human handles login/checkpoints, Premium purchase, draft review, and the final publish decision. Tweet, thread, and reply drafts do not support media; only Articles can use a cover.

## Authentication

X uses a CLI-owned Playwright persistent profile. Configure `X_USERNAME`, `X_PASSWORD`, and `X_EMAIL` before any authenticated X action—`create-watch-list`, `watch`, `draft`, `reply`, or `history`; this transport does not support manual credential entry or an unrelated Chrome session.

To establish or recover that session, the agent runs the intended authenticated action with `--inspect`—`create-watch-list`, `watch`, `draft`, `reply`, or `history`. That command opens the CLI-owned profile and continues afterward; do not stage a draft merely to authenticate read/list work. A human intervenes only if X presents a checkpoint.

Authentication can fail because credentials are missing or rejected, the persisted session expired, X requires a human challenge, the network failed, or selector drift made the probe inconclusive. Profile and cookie files are only evidence; the auth receipt is the current result.

## Platform specification and gotchas

- Tweets and replies use `twitter-text` weighted counting after NFC normalization: maximum 280; CJK and parsed emoji weigh 2, and transformed URLs weigh 23. `--long` requires Premium; its actual draftable limit remains server-authoritative.
- Supply exactly one of `--text` or `--from`; `--from -` reads stdin. X file/stdin input recognizes a BOM and LF, CRLF, or lone-CR leading frontmatter. A closed empty or YAML mapping block is metadata only: it is removed before tweet, thread, reply, reply-thread, or Article generation, every key is ignored, and an Article title is derived from the normalized Markdown body. Valid scalar/sequence blocks and thematic-break prose remain literal Markdown (apart from removal of a leading transport BOM under the shared file-input contract). Mapping-intent malformed or unterminated YAML exits 2 with actual/expected evidence before artifacts, state, profiles, browser, or API imports or writes. Inline `--text` remains literal and is never interpreted as frontmatter.
- Thread rows are split deterministically and each numbered row must remain within weighted 280. Native row verification covers only the full text of the first row, so inspect every row when full persistence matters.
- Tweet, thread, and reply generation derives a prose stream from Markdown: a leading H1 is consumed as the document title, while later heading lines, image-only lines, and `Key: value`-shaped lines among the first eight lines of the normalized Markdown body are omitted from transport text. Every such omission is emitted as an exact source-line fidelity warning; when file/stdin frontmatter is removed, that warning applies the removed-line offset and still points to the original input line. Review those warnings before accepting the draft. Tweet/thread/reply media attachments are unsupported, so a Markdown image warning is not evidence that an image was attached.
- X tweet, thread, reply, and reply-thread generation replaces every parser-confirmed top-level fenced code block with an exact numbered placeholder such as `[code block #1 → screenshot]`. The placeholder is transport text: `#1` counts as 29 `twitter-text` weighted characters in standard tweets/thread rows and 28 Unicode code points under `--long`. Literal caller transport prose matching the reserved `[code block #N → screenshot]` syntax exits 2 locally before platform/state access; the same literal inside transformed code or an omitted heading is not transported and does not collide. Each replacement emits both the existing screenshot advisory and a closed `code_block` fidelity warning with the original inclusive source-line range, explicit-versus-end-of-input closure, bounded terminal-safe info/preview text, and a SHA-256 digest of the complete LF-normalized removed segment. URLs inside removed code are not link advisories. Backtick or tilde openers/closers may be indented by zero to three spaces; the closer must use the same marker with at least the opener length and only trailing spaces or tabs, and a backtick info string cannot contain a backtick. A valid unclosed top-level fence consumes through end of input and is reported as such. Mixed-marker pseudo-closers remain fenced payload; the dedicated parser resolves stock-parser closer differences under this documented local grammar. Indented code, inline/short/escaped or otherwise ordinary fence-like prose remains literal. Parser exceptions, source-token boundaries that cannot be mapped exactly, and parser-confirmed fenced blocks nested in quote/list containers exit 2 locally with bounded evidence because exact transformation is unavailable. No platform/state access occurs on those failures. The optional voice pass is skipped whenever a code transform exists so it cannot move or rewrite placeholders. Replace every placeholder with a reviewed screenshot/image during the human draft review; the CLI does not attach one automatically.
- Stage an Article with `publish x draft --format article --from <base.md> --cover <prepared-5:2.jpg|png|webp>`. Articles require Premium and the body limit is unknown. After one transport BOM, recognized mapping frontmatter, and CRLF/lone-CR normalization are handled, the complete remaining Markdown is canonical: the clean `.x-article.md` artifact retains the consumed title line plus every body byte instead of rebuilding or trimming it. The first substantive physical line must be either one ATX H1 or one plain title (the documented `Plain title` followed immediately by a body line is supported), and its native title content is limited to plain or escaped text with representable edge characters; title formatting, links, code, entity-like spellings, and caller-owned edge whitespace/format characters reject locally. That one line is staged in the native title field, and body parsing begins at the exact following byte. A consumed H1 never causes a following body H1/H2 to disappear.
- The lossless Article Markdown subset is closed. Body blocks may be paragraphs, ATX H1/H2 headings, flat single-paragraph quotes, one tight flat bullet or start-at-1 ordered list group at a time, and top-level backtick/tilde fences. With GFM disabled, checkbox-looking bullet text such as `- [x] task` remains literal CommonMark list text rather than a task-list semantic. Inline content may be plain or escaped text, emphasis, strong emphasis, soft breaks, and title-free exact safe absolute HTTP(S) links. Active links use ordinary `[label](destination)` syntax whose raw destination bytes equal the staged href; angle-bracket, padded, multiline, titled, or backslash-normalized destinations reject locally. A nonempty spaces/tabs-only physical line rejects when the parser swallows it into a root paragraph or supported quote child instead of preserving a CommonMark paragraph boundary; tabs that remain content inside a paragraph, heading, quote, or fenced payload are preserved. Literal tabs anywhere in a list root/item reject locally because the CommonMark list tokenizer can expand them; caller-owned Unicode trim/control/format edges on body ATX headings, parser-trimmed non-CommonMark-blank list edges or continuation lines, and other source-normalized link destinations also stop before artifacts or native staging. H3-H6, Setext headings, thematic breaks, reference definitions, raw HTML, indented code, nested/loose/non-1 lists, adjacent distinct same-kind list groups, quote/list-nested fences, inline code, hard breaks, images, U+0000, unescaped entity-like spellings, empty or titled links, and unsafe active hrefs are not silently flattened: they exit 2 locally with bounded line evidence before inspection rendering, artifact writes, staging-runtime/profile/browser imports, or platform/state access. Article body images remain out of scope; rejection is not cover or attachment handling.
- A valid top-level backtick or tilde fenced block with zero through three leading spaces may close explicitly or at end of input. Invalid backtick info is not classified as a fence and must still fit the closed ordinary-inline subset; short/escaped fence-looking text can remain literal prose. Mixed, shorter, or trailing-text pseudo-closers remain payload. For a fence opened with one through three leading spaces, CommonMark removes up to that many literal spaces from every payload line; a payload line with fewer literal spaces followed by a tab exits 2 locally with exact line evidence because partial tab-column deindent is not represented. An EOF-closed block preserves its LF-normalized code payload, including trailing spaces and blank or whitespace-only lines; for an indented opener, that structured payload is CommonMark-deindented while the canonical clean artifact retains the exact normalized caller Markdown. Code remains draft-only: every recognized top-level Article fenced block has one advisory, is excluded from the native rich-HTML paste, and is counted in both verified and unverified Article handoff receipts for manual Insert → Code or screenshot review. Each advisory carries original and canonical inclusive line ranges, physical line count, fence family, closure, EOF-terminal-LF fact, an 80-code-point info projection, a 120-code-point deindented first-line preview, explicit truncation booleans, and SHA-256 of the exact LF-normalized fence slice. The digest begins at the opener and ends at the explicit closer without the following separator LF; an EOF-closed slice includes a caller-owned terminal LF, so otherwise identical EOF source with and without that LF has different identity. Accepted info/preview evidence is NFC and terminal-safe: control, format/bidi, and line/paragraph-separator scalars use an atomic visible `\u{...}` spelling before bounding. An unpaired surrogate in fenced source rejects locally because UTF-8 hashing cannot distinguish it losslessly; valid paired astral scalars remain supported. Canonical Markdown and CommonMark-deindented `ArticleBlock.text` are never rewritten for advisory safety.
- Article terminal inspection replaces each entire excluded fence with its block number and complete digest; raw code is shown only in the clean `.x-article.md` inspection artifact, never echoed to a terminal. File-backed Article dry-runs keep the bounded advisory facts in a separate `.x-article.inspection.txt` receipt so they cannot become payload inside an EOF-closed fence. URL-looking source in excluded code remains detached advisory data and never becomes an active anchor. Such fields retain their block provenance and explicit truncation booleans, with URL evidence limited to 512 code points and link-label evidence to 240 code points; the containing code-block digest preserves complete source identity. Active/non-code link facts are retained exactly and independently, even when the same URL also appears in excluded code.
- Before a real Article run loads the staging runtime, profile, or browser, it validates and freezes one closed request snapshot containing the title, canonical Markdown, block/run/mark/link, excluded-code, advisory, count, and detached cover-byte facts, and pre-renders the exact native HTML/plain inputs from that copy. It reparses canonical Markdown with the same Article parser and requires the complete code-block, code-advisory, and code-link-advisory sets to correspond, so consistently omitting structured code facts cannot expose raw fences in inspection or staging. Caller-owned values are not reread across the loader or Article Create/autosave awaits. Malformed, throwing/accessor/proxy, cyclic, sparse/oversized, count-inconsistent, or unsafe-active-href structures fail locally with bounded `save_not_attempted` evidence and exit 2. More than 10,000 Article code blocks, or more than 1,000,000 UTF-16 code units in the complete rendered code plus code-link advisory set, rejects locally rather than dropping identity facts. If the root format cannot be classified safely, that local failure remains a typed generic `save_not_attempted` boundary and names no Article or composer save mechanism. Active hrefs must use exact absolute HTTP(S) syntax without credentials, raw whitespace/control/format characters, ambiguous backslashes, or unsafe schemes; supported href bytes, including lone percent characters and percent-encoded path/query text, are retained exactly and are not decoded during safety validation. URL-looking advisories from excluded code are detached and bounded but are never rendered as anchors, so only active inline hrefs receive the active-href policy; every active href must still have an exact matching advisory string. Staging-runtime failures and native Save/autosave uncertainty remain exit 1 outcomes.
- Every Article requires one explicit `--cover <path>`. The CLI reads that regular file once before loading the staging runtime or profile, verifies JPEG/PNG/WebP magic, extension agreement, readable dimensions, and exact 5:2 arithmetic, then stages only the detached validated bytes. It never scans neighboring files and never crops, resizes, compresses, or converts the cover. Omit `--cover`, pass it to tweet/thread, or supply invalid input and the command exits 2 without platform access. After the exact file-input set returns, the Apply interaction is one-shot when one exact control is observable: `not_attempted` records no click, including a missing or ambiguous control; `delivery_unknown` records one exact click whose promise rejected; and `returned` records one fulfilled exact click. Neither the set nor Apply interaction is retried, and canonical native-state proof never rewrites that provenance.
- `publish x reply --to` uses a closed local target allowlist. The input is exact: whitespace, BOM/control characters, and backslashes are rejected. A raw ID is 5–25 ASCII digits matching `[1-9][0-9]{4,24}`; leading zeroes are rejected. A URL must use HTTPS with the exact apex host `x.com` or `twitter.com`, without credentials, an explicit port (including `:443`), a trailing-dot host, or any subdomain such as `www`/`mobile`. Scheme and host are case-insensitive. The exact case-sensitive paths are `/<handle>/status/<id>`, `/<handle>/statuses/<id>`, `/i/status/<id>`, or `/i/web/status/<id>`; `<handle>` is 1–15 ASCII letters, digits, or underscores, and one trailing slash is allowed. Percent encoding in the status path, dot/extra path segments, and URL-normalized path forms are rejected. A query and fragment are allowed and ignored only after the path validates; the reply ID always comes from the path.
- `publish x reply --dry-run` validates the reply content and target ID/URL syntax, then generates and renders a tweet or a reply thread that losslessly splits the normalized reply prose, without opening the reply ledger/reservations or reading or writing browser/profile/data-repository/SQLite runtime state. Target existence, visibility, and reply eligibility are not verified by dry-run; X remains authoritative for those checks during a real run. Reply-ledger claim/finalization is deliberately skipped: a later real run first claims the normalized target and may refuse finalized history unless `--force` is explicitly supplied; `--force` never bypasses an in-flight or retained reservation.
- Real reply runners that share the same live SQLite file atomically reserve the normalized target before browser staging and finalize durable history only after Save-phase evidence reaches finalization. `--force` may intentionally bypass finalized history, but it never bypasses an active, stale, or ambiguous reservation. Separate database files are not coordinated.
- Native staging reports one closed save phase: `save_not_attempted`, `save_delivery_unknown`, `save_delivered_unverified`, or `verified`. Tweet/thread/reply staging treats the close→Save click as the persistence action: failures before that click prove Save was not attempted, a rejected click has unknown delivery, and any failure or negative observation after the click returns is delivered but unverified. Article staging treats Create as the first may-create/autosave action; a returned Create/edit URL alone is not persistence proof. The immediate post-Create URL sample is provisional. After autosave settle, the CLI boundedly waits for an exact same-origin `https://x.com/compose/articles/edit/<digits>` URL; it accepts a late first canonical sample, but a missing/invalid late sample or two conflicting positive samples is never used for navigation or verification. Article verification reopens only that post-settle canonical edit URL and matches the complete intended title and body after the established whitespace and case normalization; prefixes, truncation, or extra tails are not positive evidence. Tweet/thread/reply content verification first takes a read-only baseline in the same CLI-owned browser context, then requires the exact canonical X Unsent/Drafts route, one visible native drafts modal, readable visible native Unsent rows, exactly one row whose dedicated content field equals the full intended tweet or first thread/reply row after only NFC and line-ending normalization, and a post-Save visible scoped-row multiset equal to the baseline plus exactly that full-text value. Background feed, navigation, modal labels, prefixes, substring matches, missing or multiple row-content fields, pre-existing identical visible rows, duplicate post-Save matches, and any other visible-row change are not positive evidence. The observation has no stable native row ID and does not prove the rendered rows are the complete drafts list or that this run caused the added value. Reply target identity is a separate closed fact. Live calibration on 2026-09-03 found no exact numeric target-id signal in the content-matched Unsent row or its reopened composer, so production cannot currently verify a saved reply draft's requested target. The requested compose URL, `Replying to` label, content/background links, and caller intent are never target proof. Consequently a returned real reply Save finalizes `staged-unverified` history and exits 1 even when its content row verifies; only a future exact-id observation structurally bound to that same matched native draft could make the reply `verified`. Top-level tweet/thread behavior is unchanged.
- Any Save/autosave delivery-unknown or delivered-unverified top-level draft exits 1 because a native draft may exist. Before retrying, compare X Unsent/Drafts or X Articles → Drafts manually in the exact CLI-owned profile used by that run. Returned Article outcomes preserve bounded body-input mode, excluded-code facts, distinct cover `requested`, `resolved`, `set`, `uploaded`, `observed`, and canonical-reopen `verified` evidence, plus the tri-state Apply provenance. Positive Article success requires a unique title/body editor root; zero pre-set dialogs and no pre-existing calibrated cover; one direct returned set on its calibrated same-parent cover input; one exact post-set Apply click when its unique control is observable; and authoritative native persistence at the same exact canonical edit URL: a unique above-title hosted cover with exact expected dimensions before reopen, exact complete title/body after reopen, and the same hosted source identity, box, and natural dimensions afterward. That complete proof may close an Apply phase of `not_attempted` or `delivery_unknown` without claiming Apply returned; missing returned-set or any weak, missing, or mismatched content/cover evidence remains unverified. A rejected native cover-input set leaves `set` unknown because delivery may have occurred and is never retried, routed through another input, or replaced by a media-button click. Every returned Article JSON receipt retains the exact Apply phase and its closed meaning in a bounded gotcha; verified non-`returned` outcomes also report the independent persistence proof. The receipt uses the frozen pre-loader copy after exact returned-handoff comparison. Never retry automatically; `--inspect` does not weaken any uniqueness or persistence gate. Save-progress errors and failure receipts are bounded and do not expose raw selectors, page text, credentials, private paths, or browser error details.
- For replies, a staging-runtime failure or typed `save_not_attempted` error releases only that run's owner-matched reservation because the browser function or native Save action was provably not invoked. `save_delivery_unknown`, an untyped error, or a malformed whole result retains the reservation. A coherent returned result keeps content-row and target-identity facts separate; any target-unverified result, or a typed `save_delivered_unverified` error without row details, atomically finalizes durable `staged-unverified` history and clears the reservation, but exits 1 even when content is positive. That row is duplicate protection, not proof a draft exists or that its native target is correct. If a matching draft exists or comparison is uncertain, do not retry or use `--force`. Only after confidently finding no matching draft in the exact originating profile may a separate explicit `--force` run intentionally bypass finalized `staged-unverified` history. Only positive content and exact-target facts together could finalize `staged` and exit 0; current production has no such target signal.
- An interrupted or delivery-unknown staging attempt retains its reservation. A 24-hour-old claim is only eligible for explicit recovery; age never deletes it or starts staging. First ensure the prior process stopped and check X Unsent/Drafts in the exact CLI-owned profile used by that run. If a matching draft exists or the comparison is uncertain, leave the reservation in place and do not retry or use `--force`. Only after confirming no matching reply draft exists, `--recover-stale-reservation-after-confirming-no-draft` clears the stale claim and exits without staging. That recovery flag cannot be combined with content, `--force`, `--dry-run`, `--inspect`, or `--long`.
- If reply-ledger finalization throws after Save-phase evidence, the finalized-history and reservation outcome is unknown; if finalization returns but close fails, the finalized status is known and cleanup failed. Both exit nonzero. Never retry automatically: inspect durable state and compare X Unsent/Drafts manually in the exact CLI-owned profile used by that run. Selector calibration and `--inspect` do not repair a ledger failure.
- Drafts and Articles must remain unposted. Treat missing verification, Premium ineligibility, selector drift, or server rejection as incomplete rather than claiming success.
- Human terminal output is a presentation-only projection of the same closed, frozen draft snapshot used for staging. Caller lines are visibly framed; LF is the only retained layout character, while CR, tabs, ANSI/C0/C1/DEL, bidi/format controls, line/paragraph separators, and literal backslashes have unambiguous visible spellings. Each field and the whole command transcript are bounded; a truncated field reports its exact original UTF-16 size and complete SHA-256 over the unnormalised UTF-8 scalar string. Unpaired surrogates or an unrepresentable/over-budget receipt exit 2 before artifacts, browser/profile, reply-ledger, or native staging. Canonical transport and content-faithful artifacts are unchanged by this terminal-only projection.
- `publish x draft ... --json` and `publish x reply ... --json` emit exactly one `publish.transport-receipt/v1` document. The same frozen receipt drives the human summary and distinguishes local/live validation, platform access, terminal draft state, verification strength/native reference, asset stages, warnings, residue, `published:false`, and exit class. Exit 0 is reserved for valid dry-run or positively verified staging; runtime/platform/state failures exit 1; caller/Commander input errors exit 2 before platform access. Real reply reservation or duplicate-ledger conflicts are state failures (exit 1), not invalid caller input.
